## Lesson 1: Up and running in three minutes (minimal loop)

**Goal:** open pi, ask a question, exit.

```powershell
# Enter the working directory and start pi in one step (PowerShell 7 supports &&)
cd D:\your-workspace && pi
```

When you see `>` you're in the input box:

| Action | Key | Note |
|---|---|---|
| Ask | just type, press **Enter** | e.g. type "what's today's date" and hit Enter |
| Interrupt | **Esc** | stop the AI mid-answer |
| Exit | **Ctrl+D** | press with the input box empty to quit pi |

> 💡 First time: just do these three things once. Everything else comes later.

## Lesson 2: Entering text, files, and images

**Goal:** type, add newlines, edit, reference files, and send images.

| Key or notation | Effect |
|---|---|
| **Enter** | Send input |
| **Shift+Enter** | Insert a newline; some Windows terminals can't distinguish it from plain Enter |
| **Ctrl+Enter** | Insert a newline in Windows Terminal |
| **Ctrl+J** | Generic alias for inserting a newline |
| **Ctrl+C** | Clear the input box; copies when text is selected |
| **Ctrl+-** | Undo recent input edits |
| **@** | Fuzzy-search and reference a file in the current project |
| `@full\path` | Reference a file outside the project or with a known path, e.g. `@D:\Pictures\screenshot.png` |

### Sending a clipboard image

On Windows, prefer:

```text
Alt+V
```

Verified locally: after **Alt+V**, Pi temporarily saves the clipboard image to a path like the following and attaches it to the input as an image:

```text
%USERPROFILE%\AppData\Local\Temp\pi-clipboard-<random-ID>.png
```

This path is a temp file auto-generated by Pi; you don't type it manually, and you shouldn't reference it as a long-term project asset. Screenshots meant to persist should be saved to your project or images directory.

Other ways to send images:

- **Ctrl+V**: some terminals paste the image directly; if you only get text or a path, use **Alt+V** instead.
- **Drag and drop**: drag the image into the terminal input area.
- **Reference a file**: type `@D:\Pictures\screenshot.png`, or type `@` and search for an image in the project.

After adding an image, continue typing your question and press **Enter** to send it all together. Whether the model can actually see images depends on it; check with `/model`, or run `pi --list-models` in the terminal to inspect the `images` column. Models without image support only receive the path or reject the attachment.

> Windows terminal behavior may differ: if Shift+Enter sends directly, use Ctrl+Enter or Ctrl+J; if Ctrl+V doesn't paste images, use Alt+V.

## Lesson 3: Managing your sessions (most important!)

**Goal:** name every conversation, find it again, never lose context.

### What is a session?

Every time you start a pi chat, that's a **session**. Sessions are saved automatically to `%USERPROFILE%\.pi\agent\sessions\` (foldered by working directory), and **you can continue exactly where you left off**.

### Naming a session (two ways)

```powershell
# Way 1: name at startup
pi -n "quick reference update"          # -n is --name

# Way 2: already inside, rename mid-session
/name quick reference update
```

### Finding previous sessions (by name)

```powershell
pi -r
```

`pi -r` opens the session picker, which supports:

| Key | Effect |
|---|---|
| **Type to search** | filter by keyword, e.g. "reference", "install" |
| **Ctrl+N** | show only **named** sessions (combine with naming above) |
| **Ctrl+R** | rename the selected session |
| **Ctrl+D** | delete a session (asks first; use with care) |
| **Ctrl+P** | toggle showing file paths |
| **Ctrl+S** | toggle sort order |

Press Enter on a selection to enter that session; the AI can read its full history.

### Other session operations

| Command | Effect |
|---|---|
| `pi -c` | continue the **most recent** session (most common!) |
| `/new` | start a brand-new session from the current one |
| `/resume` | same as `pi -r`, opens the picker inside a session |
| `/session` | view the current session's files, ID, message count, usage |
| `pi --session <ID>` | enter a specific session by ID (rarely needed; good to know) |

### Auto compaction and `/compact`

Pi supports automatic context compaction by default. **`AC`** at the end of the status bar means Auto Compaction is on; you generally don't need to compact manually at fixed percentages.

The auto trigger condition is:

```text
current context tokens > model context limit - reserveTokens
```

Default `reserveTokens` is 16,384, so the trigger percentage depends on the model's limit:

| Model context limit | Default auto trigger point (approx) |
|---:|---:|
| 128K | 87.2% |
| 200K | 91.8% |
| 1M | 98.4% |

After compaction, Pi keeps roughly the most recent 20K tokens of raw messages and organizes older content into a structured summary; goals, key decisions, progress, and file operations are preserved, but minor details may be lost.

**Practical advice:**

- Normal continuous tasks: just rely on `AC`; don't watch percentages.
- About to enter a new phase or start a very long operation: manually compact at **70%–80%** if at a natural boundary.
- No natural boundary but want headroom early: manually compact at **85%–90%**.
- Not recommended to compact frequently at 30%–60%; summarizing too early adds a model call and can lose details.

When compacting manually, you can include a summary requirement:

```text
/compact preserve goals, constraints, completed items, key decisions, file changes, verification results, open issues, and next steps
```

Plain `/compact` already produces a structured summary covering Goal, Constraints, Progress, Key Decisions, Next Steps, Critical Context, and read/modified files via Pi's default; the long-form instruction above just re-emphasizes priorities — it's not mandatory every time.

Auto compaction typically checks the threshold after a turn's response completes; if a request first fails due to context overflow, Pi can also compact and retry. With a 1M-context model, 69% hasn't reached the default ~98.4% auto trigger, so dropping from 69% to ~25% was the result of a manual `/compact`. It doesn't go to 0% because the structured summary, recent messages, system prompt, project rules, and tool definitions still occupy context.

Global config lives in `%USERPROFILE%\.pi\agent\settings.json`, defaults:

```json
{
  "compaction": {
    "enabled": true,
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  }
}
```

Not recommended to raise the global `reserveTokens` drastically for one 1M model: switching to a 128K model would trigger too early. Keep default auto compaction day-to-day and occasionally compact manually at phase boundaries.

### Recommended habits

1. New task: `pi -n "task name"` (e.g. `pi -n "Xiaohongshu copy"`)
2. Continue next time: `pi -c` resumes the most recent one
3. Looking for older ones: `pi -r` → Ctrl+N → type → Enter
4. Old sessions that were never named: press **Ctrl+R** in `pi -r` to add a name

## Lesson 4: Controlling replies, models, and the message queue

**Goal:** efficiently control AI replies, output, models, and queued messages.

| Key | Effect |
|---|---|
| **Esc** | Interrupt the AI's current answer; with queued messages it also restores them to the input box |
| **Ctrl+O** | Expand/collapse tool output (details of commands the AI runs) |
| **Ctrl+X** | Copy the AI's last reply message |
| **Ctrl+L** | Open the model picker |
| **Ctrl+P** | Switch to the next model in the main UI; toggles path display in the session picker |
| **Ctrl+Shift+P** | Switch to the previous model |
| **Shift+Tab** | Cycle thinking intensity |
| **Ctrl+T** | Collapse/expand thinking content without changing intensity |
| **↑ / ↓** | Select in lists; **Enter** confirms, **Esc** cancels |

### Sending more messages while the AI is working

| Action | Behavior |
|---|---|
| **Enter** | Queue a steering message; handed to the model after the current answer finishes its pending tool calls |
| **Alt+Enter** | Queue a follow-up; sent after the current task fully ends |
| **Alt+↑** | Pull a queued message back into the input box to edit |
| **Esc** | Interrupt the current task and restore queued messages to the input box |

> Windows Terminal may bind Alt+Enter to fullscreen by default. If Pi doesn't receive the key, unassign or rebind the fullscreen shortcut in Windows Terminal settings.

### Ctrl+G: writing long content in an external editor

**How it works:** pi writes the input box draft into a temp `prompt.md`, opens your external editor, and **reads it back after you close it** (the temp file is deleted automatically).

**Flow:** type → **Ctrl+G** → Notepad opens automatically → write, save, close → content returns to the input box → **Enter** to send.

**Want Typora instead?** Edit `%USERPROFILE%\.pi\agent\settings.json`, add one line (run `/reload` after editing):

```json
"externalEditor": "D:\storage\typora\Typora\typora.exe"
```

> ⚠️ Typora is single-instance: if a Typora window is already open on your desktop, Ctrl+G will fail (pi thinks you finished editing). **Close other Typora windows first.**

## Lesson 5: Reading the startup screen (status bar)

**Goal:** no longer be confused by the English you see at startup.

### Startup banner

```
pi v0.83.0                          ← pi version
[Context] AGENTS.md                 ← loaded project rules file
[Skills] ai-publish-analysis,...    ← loaded skills (for specific tasks)
[Prompts] /gather-context-and-clarify,... ← preset prompts
[Extensions] @juicesharp/rpiv-...   ← loaded extensions
What's New                          ← release notes for this version (ignorable)
```

There's also a keybinding hint line at the top: `escape interrupt` (Esc to interrupt), `ctrl+c/ctrl+d clear/exit` (clear/exit), `/ commands` (command menu), `! bash` (run a command), `ctrl+o more` (expand/collapse tool output). Use `/hotkeys` for the complete keybinding help.

### Bottom status bar (left to right)

```
DeepSeek V4 Flash | think:max | dir xzy_ | ⎇ main *6 +1 ?6 | ◫ 0/1.0M (0.0%) AC
```

| Content | Meaning |
|---|---|
| `DeepSeek V4 Flash` | current model (switch with `/model`) |
| `think:max` | thinking level: off / minimal / low / medium / high / xhigh / max |
| `dir xzy_` | current working directory |
| `⎇ main *6 +1 ?6` | Git status: branch `main`; `*` modified count, `+` staged count, `?` untracked count |
| `◫ 0/1.0M (0.0%) AC` | context usage: 0 used / 1M total tokens; AC = auto compaction enabled |

### Switching models and thinking intensity

| Action | Method | Scope |
|---|---|---|
| Open model picker | `/model` or **Ctrl+L** | current session |
| Cycle thinking levels | **Shift+Tab** | current session; `think:*` in the status bar changes immediately |
| Collapse/expand thinking content | **Ctrl+T** | display only; doesn't change thinking intensity |
| Set default thinking level | `/settings` → `defaultThinkingLevel` | new sessions from now on |

Thinking levels in order: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`. When a model only supports some of them, pi skips unsupported levels or clamps to the available ones.

You can also specify at startup. For example, `gpt-5.6-sol` connected via ChatGPT/Codex OAuth:

```powershell
# Specify model and thinking separately
pi --model openai-codex/gpt-5.6-sol --thinking medium

# Shorthand with model parameter
pi --model openai-codex/gpt-5.6-sol:high
```

Start daily tasks at `medium`, switch to `high` temporarily for complex troubleshooting or architecture analysis. `xhigh`/`max` are usually slower and may burn provider quota faster.

## Lesson 6: Slash command quick reference (starting with /)

Typing `/` in the input box opens the command completion menu; extensions, skills, and prompt templates may register extra commands.

| Command | Effect |
|---|---|
| `/login`, `/logout` | sign in/out of OAuth and API key providers |
| `/model` | switch the current model |
| `/scoped-models` | set the model scope and order Ctrl+P cycles through |
| `/settings` | modify common settings like thinking, theme, message delivery, transport |
| `/new` | start a blank session |
| `/name <name>` | name the current session |
| `/resume` | open the history session picker |
| `/session` | view session file, ID, message count, tokens, estimated cost |
| `/tree` | view the session tree and continue from any historical node |
| `/fork` | create a branch session from a previous user message |
| `/clone` | duplicate the current active branch as a new session |
| `/compact [requirement]` | compact older context; optional summary requirement |
| `/trust` | save the trust decision for the current project or parent dir; usually needs a restart |
| `/copy` | copy the last assistant message |
| `/export [file]` | export the session as HTML or JSONL |
| `/import <file>` | import and continue a JSONL session |
| `/share` | upload as a private GitHub Gist and generate a share link; external publishing — confirm content first |
| `/reload` | reload keybindings, extensions, skills, prompt templates, themes, context files |
| `/hotkeys` | view the complete keybinding list |
| `/changelog` | view Pi release notes |
| `/llama` | manage llama.cpp routed models; ignorable if not using local models |
| `/quit` | exit Pi |

Two shell prefixes:

| Prefix | Effect |
|---|---|
| `!command` | run a system command and send its output to the model, e.g. `!git status` |
| `!!command` | run a system command but **don't send output to the model**; handy for a quick look |

Commands run in the current project directory. Don't print secrets, cookies, full `auth.json`, or other sensitive info through commands.

## Lesson 7: Startup command cheat sheet

### Working directory and sessions

```powershell
# ★ Most common daily: enter the working directory and start Pi
cd D:\your-workspace && pi

# Continue the most recent session
pi -c

# Browse and pick a history session
pi -r

# Name at startup
pi -n "my task name"

# Enter a specific session
pi --session <session-ID>

# Temporary session, not written to session history
pi --no-session
```

### Models and thinking

```powershell
# List available models; optional search term
pi --list-models
pi --list-models openai

# Specify provider and model
pi --provider deepseek --model deepseek-v4-flash

# Provider/model + thinking shorthand
pi --model openai-codex/gpt-5.6-sol:high

# Specify thinking separately
pi --model openai-codex/gpt-5.6-sol --thinking medium

# Limit the Ctrl+P cycle scope
pi --models "openai-codex/*,deepseek/*"
```

### One-shot tasks and file input

```powershell
# Ask once, print the result, exit
pi -p "summarize the current project"

# Bring files or images at startup
pi @README.md "summarize this document"
pi "@D:\Pictures\screenshot.png" "analyze this screenshot"

# Read from stdin
Get-Content README.md | pi -p "summarize this content"
```

### Tools and startup networking behavior

```powershell
# Disable all tools; chat only
pi --no-tools

# Allow only read-only tools
pi --tools read,grep,find,ls

# Block a specific tool
pi --exclude-tools bash

# Disable startup update checks, package updates, and telemetry requests
pi --offline
```

`--offline` only disables Pi's **startup network operations**; it doesn't turn a remote model into a local one.

## Lesson 8: Model auth and config files

### Sign-in methods

Inside Pi, enter:

```text
/login
```

Two common auth types:

| Type | Example | Characteristics |
|---|---|---|
| OAuth | `openai-codex` (ChatGPT Plus/Pro) | browser authorization; tokens auto-refresh |
| API Key | DeepSeek, custom relays | static key; deal with revocation, expiry, or low balance |

With a ChatGPT subscription, choose `openai-codex/...` models; plain `openai/...` models usually belong to separately billed OpenAI API and are not the same quota.

### Three main config files

```text
%USERPROFILE%\.pi\agent\auth.json       OAuth or API keys; never share or commit to Git
%USERPROFILE%\.pi\agent\models.json     custom providers, baseUrl, models, or overrides
%USERPROFILE%\.pi\agent\settings.json   default model, thinking, theme, global settings
```

Built-in providers like OpenAI/Codex and DeepSeek may not appear in `models.json`; their model catalogs are built into or cached by Pi, and credentials live in `auth.json`.

`/session` and the bottom status bar show the current session's tokens and estimated cost, not your OpenAI or DeepSeek account balance. Remaining quota is shown on the provider's official Usage page.

## Lesson 9: Proxy, TUN, and OAuth callbacks

### Recommended: TUN only

A TUN virtual NIC takes over networking at the OS level for both the browser and Pi; usually you don't need the Windows system proxy. After OAuth browser authorization, Pi returns to:

```text
http://127.0.0.1:<random-port>/callback
```

When both TUN and the system proxy are on, the system proxy can interfere with this local callback. The locally verified combo is: **TUN on, Windows system proxy off**.

### No TUN; local proxy only

With only the Windows system proxy on, the browser usually goes through the proxy, but Pi isn't guaranteed to auto-read WinINET settings. Set it temporarily from the current PowerShell:

```powershell
$env:HTTP_PROXY  = 'http://127.0.0.1:7897'
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
$env:NO_PROXY    = 'localhost,127.0.0.1,::1'
pi
```

The port must match your client's actual port. These variables only affect the current PowerShell and the Pi it launches; they expire when the window closes.

For more complete dynamic connectivity, TUN, system proxy, and OAuth troubleshooting records, see the fcclient VPN configuration optimization report.

## Lesson 10: Common problems and the daily workflow

### Common problems

| Symptom | Check first |
|---|---|
| Images won't paste | press Alt+V instead; confirm the terminal and current model support images |
| OAuth page won't open | can the node reach `auth.openai.com`/`chatgpt.com`; is the exit region supported |
| OAuth succeeds but Pi doesn't receive it | turn off the system proxy, keep only TUN, or let localhost bypass the proxy |
| Logged in but model calls time out | can TUN actually reach the model API; with system proxy only, set `HTTP_PROXY`/`HTTPS_PROXY` |
| `/model` can't find a model | check `/login`, credentials, and `pi --list-models <keyword>` |
| thinking seems unchanged | Shift+Tab changes levels; Ctrl+T only controls display; the model may not support all levels |
| context nearly full | `/compact` to compress, or `/new` for a new session |
| can't find an old task | search with `pi -r`; name sessions with `/name` or `pi -n` |
| config changes not applied | `/reload`; restart Pi for project trust or startup-level settings |

### Recommended daily flow

1. `cd` to the project dir, start with `pi -n "task name"`.
2. Type `@` to reference files; use Alt+V for screenshots.
3. Pick a model with `/model` or Ctrl+L, thinking with Shift+Tab.
4. For complex tasks, let Pi read the rules and relevant files before authorizing changes.
5. Check context with `/session`; `/compact` when too long.
6. When done, confirm tests, Git diff, and commit; continue next time with `pi -c` or `pi -r`.

## Version and verification basis

This manual is compiled from the local Pi v0.83.x bundled docs `usage.md`, `keybindings.md`, `providers.md`, `settings.md`, and `environment-variables.md`, combined with local verification:

- `Alt+V` attaches a clipboard image to the input as a temp PNG;
- ChatGPT Plus/Pro can write `openai-codex` OAuth credentials via `/login`;
- `Shift+Tab` changes thinking, `Ctrl+T` only controls thinking content display;
- OAuth loopback callback succeeds with TUN on and the Windows system proxy off.

After upgrading Pi, run `pi --version`, `/changelog`, and `/hotkeys` first; if behavior changed in the new version, update this manual accordingly.
