一篇名为《One Token Is Enough》的论文做了一个看似简单的实验：对 165 个 AI 模型反复提问——"给我一个 1 到 100 的随机数。"

每个模型问 30 遍，再统计答案分布。

结果发现，大模型给出的数字远没有想象中随机。

## 每个模型都有自己的"幸运数字"

GPT-4o 更常回答 42、37 和 57；Claude Sonnet 5 明显偏爱 47；Llama 3.3 常选 53。

更极端的是，原帖所列的 Qwen3-Max 在 30 次测试中全部回答 42。

研究者不只测试随机数，还测试了随机颜色、动物、城市和抛硬币等 10 类任务，总计向 OpenRouter 发出约 32.6 万次请求。

结论指向同一个现象：不同模型会表现出不同、相对稳定的概率偏好。

## 缺陷反而可以变成身份证

"模型不会真正随机"并不是新发现。更有意思的是，论文把多个偏好组合起来，形成 Behavioral Fingerprint，也就是"行为指纹"。

它的用途很直接：先在可信的官方 API 上采集参考指纹，再对待验证的中转 API 采集同类答案，比较两份概率分布是否足够接近。

这能帮助判断：付费购买的某个模型接口，背后运行的到底是不是它所声称的模型。

这类问题并非纯理论。原帖还提到，CISPA 的研究人员曾审计 17 家中转 API，并用能力测试、统计检验和 LLMmap 指纹技术发现多个疑似模型不匹配的端点。

传统方法通常需要专门测试题、完整回答、模型数据库和分类器，一般用户很难使用。随机数方法的价值，是把复杂探测压缩成了不起眼的普通问题。

```text
给我一个 1 到 100 的随机数。
```

这类问题还可以换语言、换说法，不容易被中转服务识别成专门探针后临时切换模型。

## 一个 Token 能做到什么程度

论文设计的协议类似生物特征认证：对两个概率分布计算 Jensen-Shannon 散度，距离低于阈值就认为认证通过。

按原帖转述，使用全部 40 个探测单元时，判断错误率约为 7.3%；只使用 8 个单元、约 120 次请求时，错误率约为 10.6%。

研究中还出现了一个引人注意的案例：OpenRouter 上的 Palmyra X5 与开源模型 Qwen3-235B 的行为指纹非常接近。

论文作者对此保持克制，只将其描述为统计观察，而不是对意图的指控。数据和代码已公开：

## AI 为什么无法真正随机

原帖还把问题延伸到了 AI 视频中的抛硬币偏差。

真正均匀的 1 到 100 随机分布，熵应为 6.64 bit；原帖转述的 165 个模型中位数只有约 1.0 bit，说明答案高度集中、可预测。

人类其实也会出现类似偏好：更少选择重复或相邻数字，更偏爱奇数、质数，以及看起来"不圆整"的数字。7、37、42、47、53 被赋予文化意义或"看起来更随机"，反而让它们更频繁出现。

大模型从海量人类文本中学习，每一个权重都沉淀了语料中的规律和偏好。让它"随便说一个数"时，它只能生成训练数据里最像随机数的答案。

模型名称可以重写，系统提示词可以修改，接口外面也可以再套一层壳；但长期训练形成的概率习惯，仍可能从一个小小的 Token 里泄露出来。
